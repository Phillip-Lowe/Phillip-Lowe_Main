# 2026-07-03 — Utopia Deli Frontend Recovery + n8n V4 Workflow Fix

## Summary
Fixed the Utopia Deli order page after the frontend was accidentally reverted to a broken version. The payload was stripped of `item_id`, `mod_id`, `group_id` which caused the n8n V4 DB-validation workflow to fail at every step.

## Root Cause
The frontend `order-form.js` was accidentally reverted (unsaved changes in VS Code got pushed). This caused:
1. Payload missing `item_id` (sent `name` only) → `Extract Lookup IDs` returned empty arrays
2. Payload missing `mod_id`/`code` on modifiers → modifier lookups returned nothing
3. Payload missing `group_id` on modifiers → group validation failed
4. Payload wrapped in `body: { ... }` → Switch routing condition `$json.body.body.source` never matched
5. `index.html` had HTML tags stripped to raw text (favicon `<link>`, Google Fonts `<link>`, logo `<img>`, phone `<a>`)

## Fixes Applied

### order-form.js
- Restored from deployed version (which had the richer cart structure with `item_id`, `variant_id`, `mod_id`, `group_id`)
- Fixed payload construction to send `item_id`, `variant_id`, `mod_id`, `code`, `group_id`, `price_cents`
- Flattened payload (removed `body: { ... }` wrapper) so Switch routing works

### menu-data.js
- Updated to deployed version with `mod()` helper that returns `mod_id`, `group_id`, `group_type`, `price_delta_cents`

### index.html
- Restored from last good commit (`01f670c`) which had proper `<link>` tags for favicon and Google Fonts
- Removed duplicate `order-form.js` from `<head>`
- Removed broken `confirmation-trigger.js` reference (was 404)
- Updated cache busters: `menu-data.js?v=10`, `order-form.js?v=5.6`

### n8n Workflow (SQLite direct edit)
- Fixed Switch condition from `$json.body.body.source` to `$json.body.source` to match flattened payload

### Postgres
- Restarted (stale PID file, wasn't accepting connections)

### SharedWorkflow
- Added missing `shared_workflow` record for "Minimal Checkout" workflow to stop activation errors
