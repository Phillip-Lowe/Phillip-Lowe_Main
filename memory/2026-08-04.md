## Architecture Decisions

- Stayed standard-library only (`urllib`, `re`, `ssl`, `json`). No `requests`, `beautifulsoup4`, or venv.
- Email remains the canonical detailed report; on-page results are intentionally brief.
- Tier scoring is deterministic: `completed / total` per tier, with required signals weighted 80% and optional signals 20%.
- Vendor fingerprinting is simple string/URL matching against a `FINGERPRINTS` constant for easy expansion.

## Known Issues / Next Refinements

- Vendor fingerprinting can over-match. Example: zapier.com matched "Salesforce" likely from integration mentions rather than an actual Salesforce script. Next iteration should require script-src or more specific evidence for high-confidence tool detection.
- Estimated leak total can hit the cap ($30K) when many categories are missing. Review whether this feels aggressive for small businesses.
- Consider adding a small test dataset (`test_sites.json`) once 20+ sites have been scanned to prevent regression in vendor detection.

### Biggest Signal: Vendor Mention ≠ Vendor Used

zapier.com detected: HubSpot, Salesforce, Pipedrive, Monday, Acuity, Mailchimp. Likely false positives from integration marketing text. Need confidence model.

### v1.1 Fingerprint Confidence Model

```json
{
  "name": "Salesforce",
  "confidence": "low",
  "evidence": "Text mention"
}
```

Three levels:

- **HIGH**: script src, iframe, API endpoint, known asset URL
- **MEDIUM**: form endpoint, tracking code, widget references
- **LOW**: text-only mention, integration listings, blog/marketing pages

Only HIGH/MEDIUM affect maturity scoring. LOW becomes informational.

### Calibration Opportunity

systack.net = Bronze, 64/23/0 may be correct. Audit should not flatter. SyStack lacks CRM, analytics, booking, reviews, nurture automation. Credibility comes from grading ourselves the same way.
